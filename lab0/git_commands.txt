git clone <URL> — копирует удалённый репозиторий (например, с GitHub) к себе на компьютер вместе со всей историей изменений 

git status — показывает текущее состояние: какие файлы изменены, какие готовы к коммиту, а какие ещё не отслеживаются Git 

git add <файл> — добавляет файлы в «зону подготовки» (staging area). Именно те файлы, что вы добавили этой командой, попадут в следующий коммит  Вариант git add . добавляет сразу все изменённые файлы.

git commit -m "сообщение" — фиксирует подготовленные изменения в истории репозитория как «снимок» с кратким описанием . Это как сохранить прогресс в игре, только для кода.

git push — отправляет ваши локальные коммиты на удалённый репозиторий, чтобы другие участники команды увидели изменения 

git init — превращает текущую папку в новый репозиторий, создавая внутри служебную директорию .git

git pull — забирает изменения с удалённого репозитория и сразу объединяет их с вашей локальной версией. Обычно делают перед началом работы, чтобы быть в курсе чужих коммитов [2][9].

git branch <имя> — создаёт новую ветку (отдельную линию разработки). А git branch без параметров показывает список всех веток 

git checkout <имя> — переключается на другую ветку или возвращает файлы к предыдущему состоянию  Также с её помощью создают ветку: git checkout -b имя.

git merge <имя> — вливает изменения из одной ветки в текущую. Так обычно объединяют готовую работу из ветки с основной версией
